# 단계 규칙: 베타 (클로즈 베타 → 오픈 베타)

## 목표
실제 사용자 환경에서 문제를 찾아 안정화한다. 새 기능보다 버그.

## 규칙
- 새 기능 요청은 `docs/scope.md`의 다음 버전 후보로 넘기는 것을 기본으로 제안한다.
- 버그는 심각도 순으로 처리한다.
  | 등급 | 기준 |
  |---|---|
  | S1 크래시 | 앱 종료, 데이터 손실, 결제 오류 |
  | S2 진행 불가 | 핵심 기능을 쓸 수 없음 |
  | S3 기능 오류 | 우회 가능하지만 틀림 |
  | S4 사소함 | 표시, 문구, 미세한 불편 |
- 버그를 고치기 전에 **재현 테스트부터** 만든다.
- 로그·크래시 리포트를 근거로 원인을 추적한다. 추측으로 고치지 않는다.
- 기획 데이터 오류도 버그로 취급하고, 검증 스크립트에 해당 검사를 추가한다.
- 베타 피드백은 `docs/qa/<버전>/feedback.md`에 모은다.

## 응답 방식
버그 목록을 심각도 순으로. 수정마다 원인 / 수정 / 재발 방지 3줄.

## 완료 조건 (게이트)
- [ ] S1·S2 버그 0건
- [ ] 출시 체크리스트(`docs/checklists/release.md`) 전체 점검
- [ ] 릴리스 runbook 최신화
