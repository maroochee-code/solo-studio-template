# 단계 규칙: 본설계

## 목표
프로토타입에서 배운 것으로 **최종 범위, 기술 스택, 골격, 마일스톤**을 확정한다. 아직 본 코드는 짜지 않는다.

## 진행 순서
1. `docs/prototype-learnings.md`를 읽는다.
2. 기획 브리핑을 듣고, **판단에 필요한 질문을 먼저** 한다.
   (누가 유지보수, 플랫폼, 예산·서버비, 수명과 확장 계획, 외부 협력 예정 여부)
3. 기술 스택·설계 방식 후보 2~3개를 비교한다.
   (장점, 단점, 개발 난이도, 확장성, 비용, 외부 서비스 종속성) → 추천 1개
   추천하는 도구가 지금도 활발히 관리되는지 웹에서 확인한다.
4. 사용자가 고르면 `docs/architecture.md` 작성: 폴더 구조, 골격 규칙, 확장 지점, 데이터 흐름, integrations 구조
5. `docs/scope.md` 확정: 이번 버전에 할 것 / **안 할 것** / 다음 버전 후보
6. 마일스톤과 워크리스트 작성: `docs/milestones.md`
7. 필요한 실무 에이전트 구성안 제안 (hiring-proposal 양식, 처음엔 최소 인원)
8. 시작 체크리스트(`docs/checklists/start.md`) 중 현재 규모 항목 점검
9. 이 CLAUDE.md의 2장(프로젝트 개요)과 8장(명령어) 채우기

## 규칙
- 프로토타입 코드는 참고용이다. 그대로 기반으로 쓰지 않는다. 쓸 만한 부분만 옮긴다.
- 기획자(사용자)의 제안에 기술적 문제가 있으면 반대 의견을 분명히 낸다.

## 응답 방식
질문을 충분히. 결정은 선택지와 근거를 붙여서.

## 완료 조건 (게이트)
- [ ] architecture.md, scope.md, milestones.md 사용자 승인
- [ ] 첫 마일스톤에 필요한 에이전트 승인
- [ ] 시작 체크리스트 해당 항목 점검 완료
