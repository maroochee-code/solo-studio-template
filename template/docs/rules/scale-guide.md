# 규모별 적용 가이드

총괄은 현재 규모에 맞는 범위만 적용한다. 규모 기준을 넘어서면 상향을 제안한다.

## 규모 기준
| 규모 | 예시 | 기간 감 | 특징 |
|---|---|---|---|
| **S** | 엑셀 자동화, 디스코드 봇, 개인용 툴 | 며칠~몇 주 | 혼자 씀, 배포 없음 또는 간단 |
| **M** | 웹 서비스, 소규모 앱, 인디 게임 | 몇 주~몇 달 | 외부 사용자 있음, 스토어나 서버 있음 |
| **L** | 상용 앱·게임, 결제·퍼블리셔·라이브 운영 | 몇 달 이상 | 돈과 법이 걸림, 외부 협력 있음 |

## 상향 신호
- S → M: 남이 쓰기 시작한다 / 서버·DB가 필요해진다 / 스토어 출시 계획이 생긴다
- M → L: 결제가 들어간다 / 퍼블리셔·써드파티가 붙는다 / 라이브 운영을 한다

## 규모별로 켜는 것
| 항목 | S | M | L |
|---|---|---|---|
| 사용하는 단계 | 프로토타입(→바로 마무리 가능) | 프로토타입 → 본설계 → 구현 → 베타 | 전체 + 라이브 + 동결 |
| 골격 설계(architecture.md) | 생략 가능 | 간단히 | 필수 + 결정 기록 |
| 에이전트 | 없음 또는 reviewer | reviewer + 실무 1~3 | 필요에 따라 충원 |
| scope.md(안 할 것) | 3줄이면 충분 | 필수 | 필수 + 버전별 |
| 회의록·decisions.md | decisions.md만 | 둘 다 | 둘 다 |
| QA 평가지 | 생략 | 마일스톤마다 | 버전별 폴더 |
| 테스트 | 핵심만 | 기능마다 | 기능마다 + 빌드 자동화 |
| 문자열·데이터 테이블 분리 | 선택 | 필수 | 필수 + 검증 스크립트 |
| integrations/ 어댑터 | 외부 SDK 쓰면 | 필수 | 필수 + SDK별 연동 문서 |
| 스토어·법규 체크리스트 | 해당 없음 | 출시 전 | 시작부터 |
| 릴리스 runbook | 생략 | 간단히 | 필수 |
| 회고 / 포스트모템 | 끝날 때 3줄 | 마일스톤마다 회고 | 회고 + 포스트모템 |

## 하향도 있다
기획이 축소되거나 실험으로 끝내기로 하면 규모를 낮추고, 불필요해진 절차와 에이전트 정리를 제안한다.
