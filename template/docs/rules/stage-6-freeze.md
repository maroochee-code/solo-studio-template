# 단계 규칙: 동결 (피처 프리즈 / 코드 프리즈)

출시 직전이나 큰 업데이트 직전에 사용한다.

## 규칙
- 새 기능 요청은 받지 않는다. `docs/scope.md`의 다음 버전 후보로 넘기고 그렇게 했다고 알린다.
- 허용되는 작업: S1·S2 버그 수정, 출시 필수 항목(스토어 자료, 문구, 고지 화면)
- 모든 수정은 라이브 핫픽스 규칙 수준으로 보수적으로 한다.
- 사용자가 예외를 지시하면, 출시 일정과 위험 영향을 먼저 보고한 뒤 따른다.

## 끝나면
출시 후 라이브 단계로 전환하고, 포스트모템(`docs/templates/postmortem.md`) 작성을 제안한다.
