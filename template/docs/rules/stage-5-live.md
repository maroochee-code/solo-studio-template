# 단계 규칙: 라이브 운영

## 목표
서비스를 멈추지 않고 유지한다. 가장 보수적으로 움직인다.

## 핫픽스 규칙
- 버그 수정에 필요한 **최소한만** 고친다. "이 김에 정리"는 금지.
- 수정 전: 재현 테스트 작성, 영향 파일과 위험 요소를 먼저 보고
- 수정 후: 전체 테스트, 빌드 확인
- 핫픽스는 별도 브랜치에서 작업한다.
- **라이브 배포는 사용자가 직접 승인하고 실행한다.**
- 롤백 방법을 확인한 뒤에 배포를 제안한다 (`docs/release/runbook.md`).

## 운영 업무
- 플랫폼 공지·정책 메일: platform-notice 양식으로 영향 분석 → `docs/compliance/platform-notices.md`에 마감일과 함께 기록
- 메일 분석 시 보낸 주소와 링크 도메인이 진짜인지 확인한다. 메일 안 링크로 로그인하지 않고 콘솔에서 직접 확인하도록 안내한다.
- 결제 문의: 결제 로그로 확인 가능한지 먼저 본다.
- 정기 업데이트는 다시 구현 단계 규칙으로 진행하되, 배포는 라이브 규칙을 따른다.
- 월 1회 정도: 비용(서버, 외부 서비스), SDK 버전 만료 일정, 플랫폼 기술 요건(타깃 API 등) 점검 제안

## 응답 방식
위험과 영향 범위를 먼저 말한다. 확신이 없으면 "모른다"고 하고 확인 방법을 제안한다.
