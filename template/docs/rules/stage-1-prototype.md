# 단계 규칙: 프로토타입

## 목표
핵심 가치가 정말 되는지 **가장 빨리** 확인한다. 코드는 보고 버린다.

## 규칙
- 코드는 `prototype/` 폴더에만 만든다. 이 폴더는 버릴 코드다.
- 구조·테스트·문서는 신경 쓰지 않는다. 돌아가는 것이 최우선.
- 핵심 가치와 직접 관련 없는 기능(로그인, 설정, 꾸미기)은 만들지 않는다.
- `docs/risks.md`의 "가장 불확실한 것"부터 검증한다.
- 외부 서비스는 가짜(더미) 데이터로 대신한다.

## 응답 방식
짧고 빠르게. 질문은 정말 막힐 때만.

## 완료 조건 (게이트)
- [ ] 핵심 가치를 사용자가 직접 써 보고 확인했다
- [ ] 가장 큰 기술 리스크를 검증했다 (되는지 / 안 되는지)
